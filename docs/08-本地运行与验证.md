# 本地运行与验证

## 1. 运行条件

- Docker Engine 26 或兼容版本；
- Docker Compose v2；
- 至少 4 GB 可用内存和 10 GB 可用磁盘；
- 本地端口 `3000`、`8000` 未被占用。

Compose 中的数据库和对象存储凭据只用于单机开发环境，不应复制到共享或生产环境。PostgreSQL、Redis、MinIO 和 GROBID 均未发布宿主端口；浏览器只访问 Web 与 API。

## 2. 启动

先验证 Compose 的最终配置：

```bash
docker compose config --quiet
```

构建并启动完整环境：

```bash
docker compose up --build
```

`migrate` 服务会在空库上执行 Alembic 迁移。迁移成功后 API、Worker 和 Web 才会启动。GROBID 首次下载和预热通常是最慢的一步。

可用入口：

- 用户入口：<http://localhost:3000>
- API 健康检查：<http://localhost:8000/health>
- OpenAPI：<http://localhost:8000/docs>

## 3. 浏览器验证

1. 打开用户入口，选择一份带文本层、未加密的学术 PDF；
2. 点击“开始解析”，确认页面依次显示创建、上传验证和解析进度；
3. 解析完成后核对题名、作者、摘要、正文结构和参考文献；
4. 核对“参考文献、成功解析、解析失败、正文定位”四项覆盖率；
5. 点击章节或参考文献的页码，确认右侧原文打开对应 PDF 页；
6. 将浏览器宽度缩至手机尺寸，确认上传、覆盖率、列表和原文区域仍可操作。

当前切片只完成论文自身的结构与参考文献解析，不代表文本复用、引用支持、统计或图片检查已经完成。

## 4. 自动检查

本机 Python 验证：

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
.venv/bin/python -m compileall -q apps packages migrations
.venv/bin/pytest
```

前端生产产物验证：

```bash
cd apps/web
npm ci
npm run typecheck
npm run build
```

数据库迁移可在完整环境中回读：

```bash
docker compose run --rm migrate alembic current
```

## 5. 失败状态

- 非 PDF、超过 50 MB、超过 500 页、加密或损坏的 PDF 会在写入对象存储前被拒绝；
- GROBID 不可用或无法解析时，任务停在“论文解析失败”，页面提供重试，不会显示为解析完成；
- 对象下载路径同时校验任务 ID 和资产 ID；资产不属于路径中的任务时返回不存在；
- 同一源文件正在解析或已经解析完成时，重复提交解析动作不会生成新的解析运行。

排障时只记录任务 ID、阶段、计数和错误类型，不应把论文正文、凭据或用户文件名复制到日志或问题单。
