# 本地运行与验证

## 1. 运行条件

- Docker Engine 26 或兼容版本；
- Docker Compose v2；
- 至少 4 GB 可用内存和 10 GB 可用磁盘；
- 本地端口 `3100` 未被占用。

PostgreSQL、Redis、MinIO、GROBID 和 API 均不发布宿主端口；浏览器只访问带登录保护的 Web 入口。

## 2. 启动

先创建本地环境文件，将全部占位值换成独立随机凭据，再验证 Compose 的最终配置：

```bash
cp .env.example .env
docker compose -f compose.yaml -f compose.local.yaml config --quiet
```

构建并启动完整环境：

```bash
docker compose -f compose.yaml -f compose.local.yaml up --build
```

本地覆盖文件会补回 `migrate` 服务，在本地 PostgreSQL 上执行 Alembic；迁移成功后 API、Worker 和 Web 才会启动。生产环境不发布该服务，而由 GitOps 使用已绑定托管数据库的 API 镜像执行同一条 Alembic 命令。GROBID 首次下载和预热通常是最慢的一步。

可用入口：

- 用户入口：<http://localhost:3100>

登录使用 `.env` 中的 `SBDC_ADMIN_USERNAME` 和 `SBDC_ADMIN_PASSWORD`。API 仅在 Compose 内部网络提供服务，并由 Web 入口在会话鉴权后转发。

## 3. 浏览器验证

1. 打开用户入口，确认未登录时只能看到登录页；
2. 使用错误密码登录，确认不会建立会话；
3. 使用 `.env` 中的审查者凭据登录，选择一份带文本层、未加密的学术 PDF；
4. 点击“开始解析”，确认页面依次显示创建、上传验证和解析进度；
5. 解析完成后核对题名、作者、摘要、正文结构和参考文献；
6. 核对“参考文献、成功解析、解析失败、正文定位”四项覆盖率；
7. 点击章节或参考文献的页码，确认右侧原文打开对应 PDF 页；
8. 退出登录，确认工作台和后端请求都恢复为不可访问；
9. 将浏览器宽度缩至手机尺寸，确认登录、上传、覆盖率、列表和原文区域仍可操作。

当前切片只完成论文自身的结构与参考文献解析，不代表文本复用、引用支持、统计或图片检查已经完成。

## 4. 自动检查

本机 Python 验证：

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
.venv/bin/python -m compileall -q apps packages migrations
.venv/bin/pytest
```

前端生产产物验证：

```bash
cd apps/web
npm ci
npm run typecheck
npm run build
# 启动生产产物和测试后端后，在另一个终端运行：
npm run test:e2e
```

数据库迁移可在完整环境中回读：

```bash
docker compose -f compose.yaml -f compose.local.yaml run --rm migrate alembic current
```

## 5. 失败状态

- 非 PDF、超过 50 MB、超过 500 页、加密或损坏的 PDF 会在写入对象存储前被拒绝；
- GROBID 不可用或无法解析时，任务停在“论文解析失败”，页面提供重试，不会显示为解析完成；
- 对象下载路径同时校验任务 ID 和资产 ID；资产不属于路径中的任务时返回不存在；
- 同一源文件正在解析或已经解析完成时，重复提交解析动作不会生成新的解析运行。

排障时只记录任务 ID、阶段、计数和错误类型，不应把论文正文、凭据或用户文件名复制到日志或问题单。
