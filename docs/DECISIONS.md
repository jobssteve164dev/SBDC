# 架构决策记录

## ADR-001：产品是证据工作台，不是自动定罪系统

- 状态：已确认
- 日期：2026-08-26
- 决策：系统发现并解释异常，人工结合原始材料完成复核；不自动判断作者存在造假、抄袭或主观故意。
- 原因：相似文本、统计不一致和图片差异都可能有合理解释，正式定性需要语境、规范和意图证据。
- 影响：所有检测器统一输出证据卡；UI和报告不得使用不可解释的“诚信分”替代证据。

## ADR-002：使用任务级临时对照库

- 状态：已确认
- 日期：2026-08-26
- 决策：默认根据待检论文引用列表合法获取全文，只在当前任务内解析和索引；不建设长期全文对照库。
- 原因：当前需求可以通过引用范围核查完成，避免引入长期语料、版权、存储和治理负担。
- 影响：全文与FAISS索引绑定 `task_id`；报告显示覆盖范围；任务结束进入明确保留或清理流程。

## ADR-003：未引用来源追查不是默认范围

- 状态：已确认
- 日期：2026-08-26
- 决策：引用范围检查是首期默认能力。未来可以让用户对可疑段落发起外部来源追查，但候选全文仍是任务级临时资产。
- 原因：只检查引用文献无法发现未引用来源复用，但不应因此偷偷恢复长期全文库。

## ADR-004：首期采用 Python 模块化单体和专用 Worker

- 状态：已确认
- 日期：2026-08-26
- 决策：FastAPI承担 API和领域编排，Celery承担异步任务，GROBID、R和模型作为专用容器；不采用微服务群。
- 原因：PDF、NLP、统计和图片生态以 Python/R为主；模块化单体足以隔离领域，同时保持首期交付和调试闭环。

## ADR-005：FAISS承担任务级语义索引

- 状态：已确认
- 日期：2026-08-26
- 决策：首期每任务使用FAISS临时索引，不部署Qdrant或长期全文搜索集群。
- 原因：单篇论文的引用规模有限，FAISS已满足本地候选召回；数据库集群不能为未来假设提前引入。

## ADR-006：文本检测采用多阶段证据链

- 状态：已确认
- 日期：2026-08-26
- 决策：词面召回、BGE-M3语义召回、候选重排和精确片段对齐共同构成文本检查。
- 原因：逐字算法无法覆盖改写和翻译，向量相似又不能给出可靠片段与抄袭结论。
- 影响：向量分数只用于候选排序；最终证据必须展示双栏原文和精确位置。

## ADR-007：复用R统计工具而非重写

- 状态：已确认
- 日期：2026-08-26
- 决策：statcheck、scrutiny和rsprite2运行在隔离R Worker中，通过版本化JSON/CSV契约接入。
- 原因：这些方法已有现成学术实现，统一语言不足以证明重写的正确性。

## ADR-008：本地优先处理敏感内容

- 状态：已确认
- 日期：2026-08-26
- 决策：未发表论文、原始数据和原图默认只在自托管环境处理；第三方模型需要独立授权。
- 原因：论文审查材料具有保密、版权和调查敏感性。
